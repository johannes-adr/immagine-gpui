# AGENTS.md

Guidance for coding agents (Claude Code and others) working in this repository. `CLAUDE.md` imports this file.

An iOS-style Reminders + Photos demo written with GPUI (via `gpui-kit`) and compiled to WebAssembly. There are no tests and no lint config; verification is done by loading the app in a browser or the iOS Simulator.

## Commands

```sh
cargo install wasm-bindgen-cli --version 0.2.129   # must match the wasm-bindgen version in Cargo.lock
./build.sh                                         # cargo build (wasm32, release) + wasm-bindgen into www/pkg/
python3 serve.py                                   # dev: service worker disabled (kill-switch). PWA=1 python3 serve.py for the real one
# http://localhost:8080 and https://<LAN-IP>:8443 (prints both)
```

- Needs **nightly** Rust (`rust-toolchain.toml`); stable fails inside the `wasm_thread` dependency.
- If `serve.py` says "Address already in use", an old server holds the port: `lsof -ti tcp:8080 | xargs kill`. `PORT=8090 python3 serve.py` runs a second one (e.g. from a worktree; HTTPS is `PORT+363`).
- `assets/Arial.ttf` and `assets/Arial-Bold.ttf` are git-ignored but `include_bytes!`'d in `src/web.rs`; the build fails without them. The web platform ships no fonts and panics when none are loaded before the window opens.
- `build.sh` also runs `wasm-opt -O3` (binaryen) and precompresses wasm/js to `.br`/`.gz`; `brew install binaryen brotli`. Do not use `wasm-opt --all-features` (produces wasm browsers reject: "unknown import kind"); the explicit `--enable-*` list incl. `--enable-threads` is required.
- `assets/*.sub.ttf` (what the build embeds) are Latin subsets of the Arial files, made by `./subset-fonts.sh` (needs fonttools); they are git-ignored like the originals.
- Rebuild after any Rust or `vendor/` change; `www/index.html` changes need no rebuild.

## Architecture

**App (`src/`), organised by the nesting of the UI.**

```
src/
  lib.rs              module list only
  host/               THE platform seam (see "Platform rule" below)
    mod.rs              `Host` trait, shared types (`Decoded`, `Pinch`), `Current` chosen by cfg
    web/                wasm only: fetch, IndexedDB, localStorage, createImageBitmap, WebCodecs/WebAudio (codecs.rs),
                        pointer events, selftest, `entry::run` (wasm_bindgen entry: loads fonts, opens the window)
    desktop/            non-wasm: ureq, files, `image` crate, `entry::run` (native window)
  bin/immagine-desktop.rs  native entry, calls `host::desktop::entry::run`
  theme.rs            colors, glass tints, Palette (light/dark)
  util.rs             lerp, anim, spring_out, now_ms (delegates to `Host`)
  components/         reusable building blocks
    glass.rs            glass_div (liquid glass via Window::paint_glass)
    photo.rs            generated "photo" (gradient, sun, hills)
    fps.rs              FpsMeter and the FPS badge
  immagine/           the Immich photo app (root view `Immagine`, platform independent)
  app/                older Reminders + Photos demo (`Todos`), not wired into `run` any more
  logic/              pure logic, no gpui/platform imports
```

**Platform rule (hard):** platform dependencies enter the crate only through `src/host/`.
- Outside `src/host/` there is no `web_sys`, `js_sys`, `wasm_bindgen`, `wasm_bindgen_futures`, `ureq`, `std::fs`/`std::env` for app data, and no `#[cfg(target_family/target_os ...)]`. The one exception is `src/bin/immagine-desktop.rs`, which needs the cfg to compile as an empty `main` on wasm.
- `immagine/`, `app/`, `components/`, `util.rs` and `logic/` reach the platform through `host::Current` and the `Host` trait only (`use crate::host::{Current as H, Host}`). `logic/` imports not even that: it uses the traits in `logic/ports.rs`.
- Missing capability? Add a method to `Host` and implement it in **both** `host/web` and `host/desktop` (return `None`/no-op where a platform cannot do it, and say so in the module docs). Never `cfg` around a call site.
- Platform crates belong in the matching `[target.'cfg(...)'.dependencies]` block of `Cargo.toml`.
- Quick check: `grep -rnE 'cfg\((not\()?target_(family|os)|web_sys|wasm_bindgen|js_sys|ureq' src --include='*.rs' | grep -v '^src/host/'` must print only `src/bin/immagine-desktop.rs`.
- Renderer-level platform differences (WGPU vs Metal glass) live in `vendor/`, not in `src/`.

All tab code is `impl Todos` split across the child modules of `app`; the struct's private fields are visible to every descendant module, so methods that cross module boundaries are `pub(crate)`. `www/index.html` passes safe-area insets, color scheme and `!!navigator.gpu` to `run`.

**GPUI is vendored and patched** (`vendor/`, wired in `Cargo.toml` via `[patch.crates-io]`; versions must stay `0.3.10` because `gpui-kit` pins `=0.3.10`). GPUI has no backdrop blur or custom-shader hook, so the liquid-glass look is a renderer feature added here:

- `vendor/gpui-pre` (`scene.rs`, `window.rs`): adds `GlassParams`/`GlassStyle` and `Window::paint_glass(bounds, style)`. It reuses the `PaintSurface` primitive (already z-ordered and batched, previously a no-op on WGPU) with a new `glass` field.
- `vendor/gpui-pre-wgpu`: `glass.rs` + `glass.wgsl` + `glass_blit.wgsl`, hooked into `wgpu_renderer.rs` (`render_frame` creates/resizes the glass resources, `record_frame` handles the `Surfaces` batch). When a frame contains glass, everything is drawn into an offscreen texture; the backdrop is copied **once per frame** at the first glass batch; the offscreen texture is blitted to the real frame at the end.
- The glass shader uses only a uniform buffer, texture and sampler so it runs on WebGPU **and** WebGL2. iOS before 26 has no WebGPU, so WebGL2 is the path real iPhones usually take; check both.
- `vendor/gpui-pre-web` (`window.rs`): `MAX_RENDER_DPR = 2.0` caps the canvas backing-store scale (3x phones otherwise draw 2.25x the pixels).

Glass semantics to remember: later glass elements do not see content painted between glass batches; glass ignores GPUI content masks (no clipping when partly scrolled out); children of `glass_div` paint after the glass and stay crisp. The glass layer is an absolute `canvas` and needs explicit `top_0().left_0()`, otherwise it is offset by the parent's padding.

## Threads (web and desktop)

- The threading abstraction is GPUI's own: `cx.background_spawn(...)` / `cx.background_executor()`. Desktop: a native thread pool. Web: `vendor/gpui-pre-web/src/dispatcher.rs` starts `hardwareConcurrency` Web Workers via `wasm_thread` that share the wasm memory; results come back to the main thread through a mailbox woken by `Atomics.waitAsync`. It is platform-neutral gpui, so `immagine/` and `logic/` may use it without a `Host` method.
- Requirements, all in place: `build.sh` compiles with `+atomics,+bulk-memory,+mutable-globals`, `-Z build-std=std,panic_abort` and explicit linker args (`--shared-memory --import-memory --max-memory=1 GiB` plus the `__tls_*`/`__wasm_init_tls` exports; this nightly does not add them itself, without them the memory silently stays unshared). The page must be `crossOriginIsolated`: `serve.py` sends `COOP: same-origin` + `COEP: require-corp`, `sw.js` adds them to the responses it serves (static hosts get threads from the second launch).
- Without isolation (`COI=0 python3 serve.py`, same build) GPUI logs `falling back to single-threaded dispatcher` and the app runs on one thread. Check with `crossOriginIsolated` in the console and the 10 `using deprecated parameters for the initialization function` warnings (one per worker init).
- Verified: Chrome (browser pane), iOS 27 Safari (WebGPU) and iOS 18.4 Safari (prerequisites + app boots to login, WebGL2). Safari has no `COEP: credentialless`, so cross-origin subresources need CORS (our `fetch` calls do) or a CORP header.
- **How to offload work** (from a view method; the closure body runs on a worker, everything else on the main thread):
  ```rust
  self.serial += 1;
  let serial = self.serial;
  cx.spawn(async move |this, cx| {
      // Moved in by value; must be `Send + 'static`. Returns the result to the awaiting main-thread task.
      let parsed = cx.background_spawn(async move { parse(&bytes) }).await;
      let _ = this.update(cx, |t, cx| {
          if t.serial == serial { t.apply(parsed); cx.notify(); } // drop stale results
      });
  })
  .detach(); // a dropped `Task` is cancelled: `.detach()` it or keep it in a field
  ```
- **What may go into `background_spawn`:** pure Rust CPU work on owned, `Send` data: JSON parsing (`logic::json`, sync pages), store serialization (`MemoryStore` to/from bytes), `logic::range_groups`, grouping/sorting the timeline. `logic/` functions are the natural unit: they have no gpui or platform imports.
- **What may not:** anything holding `Rc`, `RefCell`, entities, `Window`/`App`/`Context`, or `Host` handles. `Host` calls (fetch, IndexedDB, localStorage, `createImageBitmap`, video, gestures) wrap JS objects that exist only on the main thread; `await` them in `cx.spawn`, then hand the bytes to `background_spawn`. Data held in `Rc<Vec<..>>` must be cloned into an owned `Vec` (or the field changed to `Arc`) before it can move; for very large data measure whether the clone costs more than the work.
- **Locks:** never block on the main thread. A contended `std::sync::Mutex::lock`/`Condvar`/`thread::join` there traps on the web (`memory.atomic.wait` is forbidden on the main thread) and stalls the UI on desktop. Pass data by value and return results through the task instead of sharing state.
- **It is not guaranteed to be parallel:** with the single-thread fallback (no isolation, old Safari) `background_spawn` runs on the main thread between frames. Split very long jobs (tens of ms) into chunks or yield, so the fallback does not freeze the UI.
- **Desktop I/O:** blocking I/O (ureq, `std::fs`) stays in `host/desktop/blocking.rs`, not in `background_spawn`; blocking the executor's pool threads starves other background tasks.
- **Timers:** `cx.background_executor().timer(d).await` inside `cx.spawn` only waits; it does not move the task off the main thread.
- Rendering and layout stay on the main thread, so threads only help once CPU work is moved off it. Boot times are unchanged (warm: first frame ~130-180 ms either way); the first cold load compiles the module per worker.

## GPUI patterns used here

- `with_animation` playback is keyed by element id; replay by changing a generation counter in the id (`tab_gen`, `press_gen`/`serial`). Animator closures are `'static` and cannot borrow `self`, so copy values into them.
- Photo viewer zoom: each grid tile has an absolute `canvas` that writes its bounds into a shared `Rc<RefCell<Vec<Bounds>>>`; `open_photo` reads them and `viewer_overlay` lerps from that rect to the full viewport. Closing flips the animation direction and a spawned timer clears `viewer` afterwards.
- Row builders that capture `cx` return `AnyElement` (an `impl IntoElement` return borrows `cx` and fails to compile).
- `gen` is a reserved keyword in edition 2024, hence `serial`.
- Tab bar and composer call `.occlude()` so pointer events do not reach the photo grid underneath.
- The FPS badge counts frames actually painted (a `canvas` paint callback) over the active span, so it reads 0/stale when the app is idle; the app does not redraw when nothing animates.

## PWA / startup

- `www/manifest.webmanifest`, `www/icons/`, `www/sw.js`. The service worker precaches the shell, JS glue, wasm and icons (cache-first). The files are not content-hashed: **bump `VERSION` in `www/sw.js` whenever any precached file changes** (every rebuild of the wasm), otherwise installed clients keep the old app. A new worker activates immediately but the running page keeps the old files until the next launch.
- `www/index.html` starts the wasm `fetch` in parallel with the JS import, shows a CSS launch screen (`#splash`) until the first frame, and logs `[boot]` timings to the console.
- `serve.py` serves `.br`/`.gz` siblings with `Content-Encoding`. Rebuild with `build.sh` (not just cargo) so they are not stale. The release profile uses fat LTO, 1 codegen unit and `strip`, so a release build takes longer.
- Service workers need a secure context (localhost or trusted HTTPS); on the iPhone with the self-signed cert they may not register. The built-in browser pane refuses to register one, so SW behavior needs a real browser.

## iOS / browser quirks

- `www/index.html` pins `html, body` to `position: fixed; inset: 0; height: 100dvh`. Without it, Safari scrolls the document and collapses its toolbar, shifting the canvas and leaving a gap.
- Safari WebGPU is secure-context only (`https` or `localhost`); `serve.py` generates a self-signed cert for the current LAN IP into `certs/` (git-ignored).
- 60 FPS ceilings are browser/display limits, not GPUI: the web platform draws on `requestAnimationFrame` and `with_max_fps` is unset.
- For iOS Simulator testing, `localhost` works directly; tap coordinates are in points (402x874 for the iPhone 16 Pro). In the desktop browser pane, click coordinates follow the screenshot's reported frame, not CSS pixels.
- **Standalone PWA (installed from the Home Screen) viewport is one status-bar height short (WebKit bug 301108 per community reports).** In the iOS 18.4 and iOS 27 simulators `innerHeight` was 812 on an 874 pt screen (62 pt = top inset), and nothing `position: fixed` paints below it, so a blank band showed at the bottom. Only the very first launch right after adding the icon got the full 874; every later cold launch got 812. Failed: `100vh`/`100dvh`/`screen.height` on fixed `html`/`body`, un-pinning GPUI's canvas size in `resize()` (canvas was 874 tall and still not painted).
  **Fix that works (verified on both simulators over repeated cold launches, no scrolling):** in `@media (display-mode: standalone)` drop the fixed pinning: `html { position: static; height: auto; min-height: 100lvh }`, `body { position: relative; height: 100lvh; min-height: 100lvh }`. Then `innerHeight`, `html`, `body` and canvas are all 874. Not tested on a real iPhone. Full log of measurements, failed attempts and sources: `docs/ios-standalone-viewport.md`. Debugging tip: show `innerHeight`, `html`/`body` heights and the canvas rect in a temporary fixed `<div>`.

## Dev workflow notes

- `python3 serve.py` serves a self-unregistering `sw.js` so reloads are never stale; `PWA=1 python3 serve.py` serves the real caching service worker. With the real one, a new `VERSION` in `www/sw.js` only shows up on the second launch (cache-first), so bump it and launch twice.
- Testing the installed PWA in the simulator: open `http://localhost:8080` in Safari, Share, "Zum Home-Bildschirm", Hinzufügen (the share sheet needs a swipe up to reveal it; the name field is focused, so tapping the wrong spot types into it). Quit the app with `xcrun simctl terminate booted com.apple.webapp` (the web clip is not a listed app and swiping it away is unreliable). Delete a stale Home Screen icon by long-pressing it, then Remove/Löschen; `apple-*` metas are only read when adding.
- Simulators: iOS 18.4 (iPhone 16 Pro, WebGL2) and iOS 27 (iPhone 18 Pro, WebGPU) are both installed; pass `device` to the simulator tool. On iOS 26+ Safari the share sheet is behind the page-menu button (left of the URL) > Teilen > Mehr anzeigen > Zum Home-Bildschirm. The screenshot tool can lag one step behind a tap, so take a second screenshot before concluding.
- A screenshot that looks frozen (same FPS badge numbers after relaunch) means the app was resumed, not restarted.
- Debugging layout inside the PWA has no console: add a temporary fixed `<div>` that prints `innerHeight`, `screen.height` and the canvas rect, and remove it afterwards.

## Immagine port

Porting Robin's Immagine (`../immagine`, Swift/iOS, clone of github.com/RobinCoding/immagine) to this app; plan and agent split in `docs/immagine-port-plan.md`.

- **Platform seam:** `src/host/mod.rs` defines the `Host` trait (transport, clock, origin, settings, blob store, image decoding, video decoder + audio output, touch gestures). `host::Current` is chosen by cfg: `host/web/` (wasm: fetch, IndexedDB, localStorage, createImageBitmap, WebCodecs + WebAudio, pointer events, `entry::run`) or `host/desktop/` (everything else: `ureq`, files under `IMMAGINE_DATA_DIR` / the user data dir, `image` crate; video decoder + audio output only on macOS/iOS (VideoToolbox, AudioToolbox), none on other desktops; touch gestures only on iOS). `immagine/`, `app/`, `logic/` use only `Host`; no `web_sys`/`wasm_bindgen` outside `host/web`. New platform feature = new `Host` method + both impls.
- Desktop build: `cargo run --bin immagine-desktop` (server from `IMMICH_URL`, default `http://immich.server.local`; 402x874 window). Glass on macOS/iOS comes from a Metal pass in the vendored `vendor/gpui-pre-apple` (`metal_renderer.rs` + `glass.metal`, which is `glass.wgsl` run through `naga` with the bindings set by hand: keep both in sync when the look changes). With glass in the frame the scene is drawn offscreen, copied once into a backdrop texture at the first glass batch and blitted to the drawable; `PaintSurface.image_buffer` is `Option` (None = glass). Glass look flag: `set_glass_variant(n)` (0 = original, 1 = Apple-like, the default, with edge lensing, clearer middle, specular rim, drop shadow; one shader, branch on `Params.extra.x`). Default is 1; `?glass=0` (web) / `IMMAGINE_GLASS=0` (desktop) selects the original. After editing `glass.wgsl` run `vendor/gpui-pre-apple/regen-glass.sh` (needs `cargo install naga-cli`). Light/dark follows `Window::appearance()` (also live). Desktop gaps: video playback on non-Apple desktops (no decoder behind `Host::video_decoder`) and single-finger viewer drag (that comes from `Host::install_gestures`, which is `None` here).
- Platform-independent logic lives in `src/logic/` and must not import `gpui`, `web-sys` or `wasm-bindgen`. Test it natively with `cargo test --lib` (the crate is `rlib` + `cdylib`).
- The module is called `logic`, not `core`, to avoid clashing with the `core` crate.
- `serve.py` proxies `/api/*` to `IMMICH_URL` (default `http://immich.server.local`), so the page is same-origin. Credentials for E2E come from the environment (`E2E_SERVER_URL`, `E2E_EMAIL`, `E2E_PASSWORD`), never from files in the repo.

- Full knowledge dump of the port (architecture, Immich API, GPUI-web findings, performance numbers, gotchas, open items): `docs/immagine-wissensdump.md`.
- **Simulator Safari keeps old ES modules** across reloads of the same tab: after a rebuild it may fail with `LinkError: import function ./gpui_web_demo_bg.js:__wbg_... must be callable` (stale JS glue, new wasm). `serve.py` now sends `Cache-Control: no-store`; if it still happens, `xcrun simctl terminate booted com.apple.mobilesafari` and reopen the URL (add `?x=N`).
- Typing the Immich password into the app's login form is left to the user (the agent does not enter real passwords); to test the logged-in app in the browser pane, set `localStorage["immagine.token"]` from a `fetch('/api/auth/login')` response, the cookie comes with it. In the simulator there is no console, so the user logs in by hand once (the token persists in that Safari's localStorage).
- **Direct to Immich (no `serve.py`):** the login screen has a server field; the choice is saved as `immagine.server` and `Host::origin()` returns it (web: falls back to the page origin, desktop: falls back to `IMMICH_URL`). All requests carry the bearer token; videos on another origin are fetched into a blob URL. Needs CORS on the reverse proxy in front of Immich, snippet and limits in `docs/direct-immich.md`. The service worker ignores other-origin requests. Not yet tested against a CORS-enabled server.

## Search

- `src/immagine/search.rs`: opened by the lupe button at the right of the range bar (`tab_bar.rs`, "range-search"); while open, `search_bar` (glass field + close circle, rides above the keyboard via `Window::visual_viewport_bounds`) replaces the tab/range bars. Tap handlers call `focus_search` (`Window::request_virtual_keyboard`): the web platform only summons the iOS keyboard for taps on the text itself, so taps on the pill or the lupe must request it explicitly (`Immagine::search`, `open_search`/`close_search`; shown instead of the timeline while `search.open` on tab 0). Text field with 400 ms debounce (Enter searches at once), modes **Kontext** (`ImmichClient::smart_search`, `POST /api/search/smart`, CLIP, relevance order) and **Dateiname** (`filename_search`, `POST /api/search/metadata` with `originalFileName`), media filter Alle/Fotos/Videos. Results are not stored; a `serial` drops stale answers. Not yet done (Immich has them): filters for people, places, camera, date, favorites, and the explore/suggestions page.
- Immich reference for server DTOs and the mobile app: sparse-clone `github.com/immich-app/immich` (`git clone --depth 1 --filter=blob:none --sparse`, then `git sparse-checkout set --skip-checks server/src/dtos/search.dto.ts mobile/lib/models/search`) into a scratch dir; search DTOs are in `server/src/dtos/search.dto.ts`.
- **Mediathek range views:** `range_mode` (0 Jahre, 1 Monate, 2 Alle, set by the range bar in `tab_bar.rs`) picks the view of tab 0. Jahre/Monate (`immagine/range_views.rs`) are derived from the in-memory timeline by `logic/range_groups.rs` (no `/timeline/buckets` calls; items carry `date_bucket`), cached by `Rc` identity in `range_cache`. Both are fixed-row-height `uniform_list`s laid out like `photo_grid` (spacer rows + shifted box). Month rows show the busiest day big plus up to three more days. Tapping a year jumps to Monate (`months_jump`), a day jumps to Alle (`timeline_jump`, handled in `photo_grid`). `sync_range_bar` never flips back to the tab bar while `range_mode != 2`; the Mediathek circle sets mode 2 and the tab bar.
- **Glass selection thumb** (`immagine/slider.rs`): one `Slider` (drag, bubble, slide, tap) shared by the tab bar (`Bar::Tabs`) and the Jahre/Monate/Alle bar (`Bar::Range`); each bar passes geometry via `Bar::geometry` and an `input_layer(view, bar, bounded)`. Do not add a second thumb implementation. A glass with `k <= 0` paints nothing (`glass_div_with`): a faded glass would otherwise still blit the backdrop snapshot over earlier glass (the tab bar's invisible thumb wiped the range bar's left part during the swap).

## Timeline grid zoom

- Levels `ZOOM_LEVELS = [1, 3, 5, 15]` (`logic/grid/layout.rs`). Default 3 columns below 700 pt width, 5 above (`grid_default`, follows the width until the user zooms; the width is not final at the first frame). `grid_cols` is the settled layout (photos per row), `grid_f` the live column count that sets the cell size. While pinching only the cell size changes (rows keep `grid_cols` photos, centered, so nothing reflows and the grid scales about the screen middle); reflowing on every column-count step flickered badly. Pinch input: touch via `Host::install_gestures`; desktop `PinchEvent` and ctrl+wheel through `grid_input` (capture-phase window listeners; gpui negates the browser's `deltaY`, so pinch-out is dy > 0). On release `grid_settle` picks the level (next level only past `SNAP_AT` of the way in log scale, else springs back); `grid_tick` (from `render`) animates `grid_f` there, fades the photos out at the end, switches `grid_cols` and fades them back in. While zooming (`grid_zooming`: pinching, settling, fading in) the anchor photo stays put through a pixel-exact `set_offset` every frame: `grid_begin` takes the photo under the screen middle and its fraction within the row from the current offset and the last layout (`grid_geom`), so nothing jumps at the start or at the level switch. **The cell size must be whole device pixels** (`(cell * scale).floor() / scale`): layout rounds the uniform list's row height, and with ~8000 rows a 0.2 px difference put the list up to 10 rows away from the computed offset, alternating every frame (the "flicker" on iPhone, worst near the newest photos). While zooming, touch scroll events are swallowed and momentum cancelled (the pinch's first finger is a pan for GPUI), and `sync_range_bar` keeps the current bar. Testing pinches: the iOS Simulator tool's `touch2_path` plus `xcrun simctl io <udid> recordVideo` and ffmpeg frames work; the hidden browser pane throttles rendering too much.

## Grid thumbnails

- `immagine/thumbs.rs` loads all renditions. Grid tiles call `get_sized(store, key, side_for(cell, scale), url, cx)`: the image is decoded with its short side scaled down to a bucket (64/96/128/192 px, else full; `Host::decode_bytes(bytes, min_side)`, web draws the bitmap into a smaller `OffscreenCanvas`). A smaller entry is shown upscaled while a bigger one loads.
- Load order: downloaded asset (`downloads` db) -> persistent cache db `thumb-cache` (`THUMB_CACHE_DB`, encoded WebP bytes, key `t:<id>:<url-encoded thumbhash>`, ~10 KB each, capped at 40 000 entries oldest-inserted first, key index kept in memory from `blob_keys` at start, cleared at logout and by the settings row) -> network (`Host::fetch_image(url, &Cancel)`). Same code on desktop (files) and web (IndexedDB). Verified: a reload of the grid makes zero thumbnail requests.
- Thumbnail URLs come from `thumbs::thumb_url` and carry `&c=<thumbhash>` like Immich's web client, so an edited photo gets a new URL and cache key.
- `photo_grid` reports the scroll offset each frame (`track_scroll`, not while zooming). Above 3 pt/ms no new loads start (tiles show their thumbhash); a 150 ms wake-up re-renders so loads start once the fling slows or stops dead.
- Prefetch: while nothing visible waits, `photo_grid` hands the next screenful of rows in the scroll direction to `thumbs::prefetch` (low-priority jobs; a visible request promotes them). At the end of the timeline, where it opens, the rows above are warmed.
- The RGBA->BGRA swap and `RenderImage` construction run in `background_spawn` (`pump`), only the atlas insert stays on the main thread.
- Concurrency: `MAX_ACTIVE` 16 loads, of which at most `MAX_NET` 6 use the network; "cheap" loads (stored download or persistent thumbnail cache) are never held back by a fling. Failed loads retry by time (`RETRY_MS` x tries, a timer re-renders the view), not by frames: Alben do not render continuously and used to never retry. Every view that shows thumbnails must call `begin_frame` once per render (`album_browser` does).
- Running `t:` loads not asked for in `STALE_FRAMES` frames are aborted (`host::Cancel`; web: `AbortController`, desktop cannot abort ureq and only skips the decode). Previews/full sizes are never aborted.
- Every load has a deadline (`THUMB_TIMEOUT_MS` 15 s for `t:`, `LARGE_TIMEOUT_MS` 120 s otherwise): then it is aborted, its slot freed (`Thumbs::release`, matched by job `seq`, so a late answer is dropped instead of freeing a slot twice) and it counts as failed (retried). Before, a request that never answered held one of the `MAX_NET` slots for good, and a view that does not re-render (Alben) never aged the frame-based abort either.
- Debug line (setting "FPS anzeigen" / `immagine.debug`): the Alben browser and album page show `Thumbs::stats()` under the title (queue, running, slots, net slots, failed keys, images, MB, ok/err/abort/timeout counters, `held`, last error), the browser prefixed by cover counts (`covers <with cover>/<tiles> hash<with thumbhash> loaded<n>`). `run` != `slots` means a leaked slot. In the browser pane (Chrome, WebGPU, desktop and 402 pt width) covers and album grids load fine; the "no images in Alben" report is from the phone, not reproduced here.
- `serve.py` sends `no-store` only for non-`/api/` paths (Immich's own `private, max-age=86400` reaches the browser) and keeps proxied responses with a length on a keep-alive HTTP/1.1 connection.

## Video player

Videos are played by the app itself, no `<video>` element and no browser controls.

- `logic/movie.rs` (pure, unit-tested with `logic/testdata/tiny.mp4` (moov first) and `tail.mp4` (moov after mdat)): the `mp4` crate parses `ftyp`+`moov`, builds the `avcC` record and the AAC AudioSpecificConfig WebCodecs needs; the sample table (pts, duration, key flag, file offset, size) is built by us from `stbl` (stsz/stsc/stco|co64/stts/ctts/stss, no sample is read), `video_start_for`/`audio_start_for` pick the keyframe/sample to seek to. **H.264 + AAC only**; HEVC/VP9 return an error ("nicht H.264") because the `mp4` crate has no usable `hvcC`. **Streaming:** `HeaderScan` walks the top-level boxes (32/64-bit and "to the end" sizes) over a `ByteCache` (non-overlapping loaded spans) and says which range to fetch next until `ftyp` and `moov` are cached (moov after mdat costs the head, one header probe, the exact moov); `Movie::open_header(ftyp, moov)` parses only those two boxes; `Movie::wanted` gives the merged byte ranges (gaps < 256 KB merged) of the samples to decode next, `next_request` the next 1-4 MB request, `Movie::next_chunk(track, i, &cache)` returns `Fetched::{Ready, Missing, End}`. `Movie::open(bytes)` (whole file) uses the same table and keeps the bytes as a cache (`take_cache`); fragmented MP4 (moof/mvex) is only supported through that full-download path, indexed by reading every sample.
- `Host::fetch_range(url, start, end_inclusive) -> RangeResponse { bytes, total, partial }` (web: `fetch` with `Range` + bearer token, total from `Content-Range`, which must be CORS-exposed on another origin or the player falls back to a full download; desktop: ureq). 200 instead of 206 = server ignored Range, body is the whole file.
- `host/mod.rs`: `VideoDecode` (decode/queue_len/reset/flush/error) and `AudioOutput` (configure/decode/reset/`start_clock`/`clock_us`/`set_paused`) ports, handed out by `Host::video_decoder(config, on_frame)` and `Host::audio_output()`. `host/web/codecs.rs` implements them with WebCodecs `VideoDecoder`/`AudioDecoder` (declared by hand with `wasm_bindgen`, `web-sys` has no stable bindings) and a WebAudio `AudioContext` that doubles as the playback clock (anchor = context time and media µs; paused = `suspend()`). Frames are drawn to a reused `OffscreenCanvas` (`willReadFrequently`, longest side capped at 1280) and read back as RGBA. macOS and iOS implement them natively, see "Native video and audio"; other desktops return `None` for both (`NoVideoDecoder`/`NoAudioOut`) and show "Auf diesem Gerät lassen sich Videos noch nicht abspielen".
- `immagine/video_player.rs` (`Player`): state machine behind the viewer. `Player::open` is called from the tap on "Abspielen" because the `AudioContext` can only be unlocked inside a user gesture. `tick` (from `viewer_overlay`, once per frame while busy, `request_animation_frame`) takes in the opened movie, arrived ranges and decoder frames and starts the clock when the first frame at/after the target exists, shows the newest frame whose pts <= clock, feeds the decoder (<= 6 queued, <= 8 decoded waiting) and audio (2 s ahead), flushes at the end (without `flush` the B-frame delay swallows the last 2 pictures) and frees replaced images with `Window::drop_image`. Seek = decoder `reset` + restart at the keyframe before the target; frames before the target are shown in passing while paused. Scrubbing pauses, previews every 120 ms and seeks for real on release.
- **Streaming in `Player`:** `open_movie` (one `cx.spawn`) requests `bytes=0-262143`; only a 206 with a known total continues, anything else (200, no `Content-Range`, moov unreachable/too big, fragmented, parse error except unsupported codec) falls back to `Host::fetch_bytes` + `Movie::open` (the fully cached file, no further requests). The moov is parsed on a worker (`background_spawn`). While playing, `request_more` (from `tick`) keeps **one** range request in flight (tagged by `serial`; results arrive through the `Inbox` and `AsyncApp::refresh` wakes the frame loop) for the bytes of the next ~10 s / 8 MB past the feed position, and keeps everything loaded in memory until it exceeds `MEM_BUDGET` (96 MiB; then `ByteCache::evict_far` drops the spans farthest from the playhead down to 3/4 of it, the span at the playhead never), so jumping back and forth does not reload. Files bigger than the budget are also written through to a disk cache (`Host::blob_put` in db `video-cache`: IndexedDB on web, files on desktop; key = span start, indexed in `Player::disk` once the write is done) and an evicted span is read back from there (`RangeDone.disk`) instead of downloaded again; the cache is cleared with `Host::blob_clear` whenever a player opens, a failed disk read just forgets the span. `feed` only decodes samples whose bytes are cached; if the video feed is starved and no picture is left (`pending` empty, decoder queue 0) the player is `buffering`: the controls show "Lädt …" instead of the time, audio is `set_paused(true)` and the wall clock stands still, both resume when bytes arrive. `seek` bumps `serial` (the answer in flight still fills the cache but is no longer awaited) and the next tick requests the spans from `video_start_for`/`audio_start_for`. Three failed requests in a row (1 s apart) fail the player. Known gap: if only the audio bytes are missing while video continues, sound drops out without a buffering state.
- **Native video and audio (macOS + iOS):** `host/desktop/apple_video.rs`, `apple_audio.rs`, hand-written FFI in `apple_ffi.rs` (frameworks linked with `#[link]`, no Cargo changes). Video: a decode thread owns the `VTDecompressionSession` (BGRA output, synchronous so VT outputs in decode order); `decode`/`flush`/`reset` only send channel messages; BGRA->RGBA with a box filter down to 1280 px longest side happens on that thread; a reorder buffer by pts (depth from the SPS `max_num_reorder_frames`, else the DPB size; also releases a picture that directly follows the last released one) feeds a `Mutex<VecDeque>` mailbox that `queue_len()` drains into `on_frame` on the main thread (`try_lock`). `queue_len` = unprocessed messages + undelivered pictures (so `tick` keeps running until the last picture is out). `reset` bumps a serial: old samples/pictures are dropped, the thread waits for a keyframe. `kVTInvalidSessionErr` (iOS backgrounding) drops the session and rebuilds it at the next keyframe; other VT errors, incl. bad data, latch into `error()` until the next `reset`. Audio: `AudioConverter` (AAC to float PCM, the ASC wrapped as `esds` cookie) runs inside `decode` on the main thread (microseconds per packet); output is an output `AudioUnit` (`DefaultOutput` on macOS, `RemoteIO` on iOS, always stereo, mono duplicated) whose render callback pulls timestamped PCM segments from a queue it owns (fed by an mpsc channel, no shared lock) and plays sequentially, re-syncing only when 30 ms off. The clock is `mach_absolute_time` (anchor + elapsed, frozen while paused), so it keeps running without sound; the callback maps `AudioTimeStamp.host_time` to media time. iOS sets `AVAudioSession` to playback + active in `configure`. More than 2 audio channels: `configure` returns false (no sound, no downmix). H.264 + AAC-LC only (HEVC is rejected by `logic/movie.rs` before it reaches here).
- Tests (all real execution, `cargo test --lib apple_` and `plays_a_local_file`): decode of `tiny.mp4`/`tail.mp4` (30 frames, pts strictly increasing, B-frames), seek via `reset`, garbage/bad avcC errors, scaling, audible-frame counter in the render callback (tests mute the device), clock/pause/reset, and the real `Player` against a local range server (`video_player.rs` tests: stream open, decode, seek, play to the end, replay, pause). `IMMAGINE_TEST_CLIP=/path/x.mp4 cargo test --lib long_clip -- --nocapture` runs any H.264 file. The same tests pass in the iOS simulators: build with `cargo test --lib --target aarch64-apple-ios-sim --no-run` and run the binary with `xcrun simctl spawn <udid> <binary> <one filter>` (one filter only). Not tested: a real device, an actual Immich login, HE-AAC, >2 channels.
- `immagine/viewer.rs` `video_controls`: glass pill (play/pause glyphs in `icons.rs`, scrubber with a `canvas` measuring the track, times); the track's mouse-down calls `cx.stop_propagation()` so the page swipe does not start, and `drag_move`/`drag_end` hand the pointer to the scrubber while it is dragged. Chips and the pill use `.occlude()`, otherwise a click also reaches the viewer's tap-to-hide-controls handler underneath.
- Test without a UI: in the console, `m = await import('/pkg/gpui_web_demo.js'); await m.video_selftest('/some.mp4')` demuxes + decodes through the real adapters and reports frames/audio (expect all frames out, ordered, audio configured). `await m.video_selftest_ranged('/some.mp4')` does the same through the streaming path (206 range requests, header-only parse, on-demand samples, then a seek into the middle with an empty cache) and lists every request; `serve.py` answers single `Range` requests for static files for this (files must be bigger than 256 KB to exercise more than the head request). End to end without an Immich server: set `immagine.token`, point `immagine.server` at the page origin and have the proxy answer `/api/assets/<id>/video/playback` with an MP4 (temporary hook that opens the viewer on a fake `VIDEO` item), then click "Abspielen". Remember the browser pane keeps `immagine.server` from earlier sessions.

## Sheet and settings

- `components/sheet.rs`: reusable bottom sheet (HIG "Sheets"). `Sheet` is a `Cell` of a `Copy` state (`shown` 0..1, open/close eases from the clock in `tick`, called from `render`; spring-back and close on release use the same animation). `overlay(...)` builds scrim + rounded panel + glass close circle (`fresh_backdrop` glass, the panel is opaque) and wires mouse drag; touch drags come from the raw `Host::install_gestures` events, which `Immagine::pinch` routes to `settings_pinch` while `sheet.visible()`. Release closes when pulled down past 25 % of the height or flicked down (> 0.6 px/ms), else springs back. Only a press on the 72 pt title strip (`sheet::HEADER`) grabs the sheet, and `shown` is clamped to <= 1 (the panel never lifts off the bottom edge).
- **Settings content scrolls** in an `absolute` div from `top(HEADER)` to `bottom_0` (top + bottom = definite height, so `max_offset` is the overflow) with `overflow_y_scroll` + `track_scroll`: mouse wheel and touch both work through GPUI's normal scroll path (touch pans become `ScrollEvent`s at the finger; the content is in front of `sheet-root`'s `.occlude()`, so it gets them). While the sheet is visible the root's `rubber_band::input` routes touch steps to `settings_scroll_event`: the sheet has its **own** `RubberBand` (`SettingsState::rubber`; the page's shared one would also bounce the grid behind the scrim), and steps are swallowed while the title strip drags the sheet, so the list does not scroll along. Verified in iOS 27 Safari (simulator) and Chrome. If it "does not scroll" on a phone, first check the PWA version row: with `PWA=1` the old wasm runs until the second launch after a `VERSION` bump.
- `immagine/settings.rs`: the settings sheet, opened by the gear (`Glyph::Gear`) at the top right of the Sammlungen browser. Shows per category (sync store, `downloads` (asset count = keys without a colon), `thumb-cache` with a "leeren" row, `video-cache`) entry count (`Host::blob_keys`) and bytes (`Host::blob_size`), used/quota, PWA version (`Host::app_info`: the `immagine-vNN` cache name of the service worker, so it is "nicht installiert" under the dev kill-switch), standalone mode, renderer (WebGPU or WebGL) and thread availability. Checked logged in in the browser pane.
- **Bump `www/sw.js` `VERSION` on every rebuild you want a PWA client to pick up**: the first Sheet fixes were built without a bump, so the installed app kept the old wasm under the same "v34".
- **Downloads** (`immagine/downloads.rs`): the viewer's top-right button stores the original in IndexedDB db `downloads` (key = asset id, `Host::blob_put`); `Host::blob_keys` lists the stored ids at start (`Downloads.ids`, shared with the grid's row builder). The grid marks stored photos with a tiny tray+check at the bottom right (beside a video's length) and favorites with a white heart at the bottom left. Logout clears the db. Nothing reads the stored bytes back yet (no offline viewing).
- **Offline / cache first for downloads:** db `downloads` holds the original (photos) or the `video/playback` H.264 file (videos) under the bare asset id, plus `t:<id>` and `p:<id>` (thumbnail and preview, fetched at download time). `thumbs::pump` reads `t:`/`p:`/`f:` keys of downloaded assets from there (`Host::decode_bytes`; `f:` decodes the stored original) before `decode_url`; `Player::open(url, local_id, cx)` plays a downloaded video from the stored bytes (`open_full`) without requests. `Thumbs.local` shares `Downloads.ids`; never replace `downloads` wholesale (clear it), or the sharing breaks. Downloads made before this change have no `t:`/`p:` entries (grid still needs the network for them; download again). Not done: EXIF/info panel offline, timeline sync offline (it shows the stored snapshot).
- Tapping the viewer's download button on a stored photo deletes it (`Host::blob_delete` for the bare id, `t:<id>`, `p:<id>`); no confirmation.

## Jobs (background downloads)

- Pure model in `logic/jobs.rs` (`Job`, `JobState` Running/Paused/Done/Cancelled, `record`, `runnable`, `listed`, `prune` keeping the last `KEEP_FINISHED` = 3 finished, unit-tested). Runner + sheet in `immagine/jobs.rs` (`JobsState` in `Immagine::jobs`).
- Each job is one JSON entry in the blob db `jobs` (key = job id), written on every state change and at most every 1.5 s while it runs. `jobs_load` runs from `load_downloads` once the stored ids are known, then `jobs_pump` continues the oldest `Running` job (paused ones stay paused). An installed PWA only runs while open; after a restart the items since the last save are seen as stored and count as "schon vorhanden".
- One runner loop at a time, one item at a time, through `downloads::fetch_and_store` (same path as the viewer's download button: thumbnail, preview, original/H.264 in 2 MB ranges, progress in `Downloads.busy`). Pause/cancel is checked between the ranges (`keep_going`), so a big video stops mid-way and restarts from scratch on resume. `serial` bumps at logout (stops the loop); logout clears the db.
- Running time is summed per job (`active_ms`, `JobsState::tick`), so pauses and restarts do not count; the sheet shows count of total, skipped, failed, MB, running time, average MB/s, the current item's percent and the last error.
- Sheet: the list button (`Glyph::Jobs`, blue badge = unfinished jobs) left of the gear in Sammlungen; a second `Sheet` routed like settings (`jobs_pinch` from `Immagine::pinch`, `jobs_scroll_event` from `render`'s rubber-band input). Verified in the iOS 27 simulator: job progress, pause, reload stays paused, resume + immediate reload continues and finishes.

The Xcode wrapper (`ios/`) replaces its placeholder executable with the Rust binary after Xcode's signing step, which strips the signature, so the script signs again with the first "Apple Development" identity and the `.xcent` entitlements. Device builds are always release; a free Personal Team profile expires after 7 days.

## Sharing (native)

- `Host::share_file` on iOS/macOS lives in `src/host/desktop/share.rs` (objc2). The bytes go to `<tmp>/immagine-share-<n>/<name>`; iOS presents a `UIActivityViewController` from the topmost view controller of the foreground active window scene (iPad: popover anchored in the middle, else it crashes) and resolves in `completionWithItemsHandler`; macOS shows an `NSSharingServicePicker` at the bottom left of the key window and resolves when its delegate reports the choice (`None` = cancel). Cancel = `Err("AbortError: ...")`, which `share_current` ignores. Other platforms keep an `Err`. iOS deletes the temp folder after the sheet; macOS leaves it (the service may still read it) until the next share.
- `share_current` (viewer): fetches the asset record (name, size), shares a stored download from the `downloads` db without a request, else photos via `original`, videos via the `video/playback` URL (range probe for the size; refused above `SHARE_MAX_BYTES` = 200 MB, since the bytes are held in memory and copied on web). Name = original stem + extension sniffed from the bytes actually sent (`share_name`: an edited JPEG of a HEIC is `.jpg`, a transcoded video `.mp4`). The busy status clears right before `share_file` is called.
- macOS calls `activateIgnoringOtherApps` before showing the picker (it cancels at once when the app is not active). Not verified on screen.

- Viewer "..." button (`Glyph::More`, replaces the download button; shows the download progress ring around the dots) opens `more_menu`: Herunterladen (`download_current`, stored = "Heruntergeladen", tap deletes), Archivieren / Aus Archiv holen (`archive_current`), Zu Album hinzufügen (album picker for the shown asset). The menu resets with `Viewer::reset_view` (page change) and when the viewer closes.
- Archive: `AlbumOpKind::Archive/Unarchive` (asset-only ops like trash/favorite), `Store::set_visibility` / `is_archived`, `ImmichClient::set_visibility` = `PUT /api/assets {ids, visibility: "archive"|"timeline"}`. An archived photo leaves `fetch_timeline` (and the viewer list, `viewer_drop`) at once; unarchiving rebuilds `Immagine::items` from the store.
- `immagine/album_picker.rs`: the album picker is a `components::sheet` (own `Sheet` + `RubberBand` in `Immagine::picker`, routed like jobs: `picker_pinch` first in `Immagine::pinch`, `picker_scroll_event` in render's rubber-band input, drawn after the viewer so it covers it). `open_album_picker(ids, from_selection, cx)`; a pick queues `AlbumOp::add`, closes the sheet, ends select mode when it came from the selection.
- Viewer info panel: values wrap (`min_w_0`), the panel is capped below the top bar and its lines scroll in `viewer-info-scroll` (`Viewer::info_scroll`). Raw touches (`Host::install_gestures`) have no hit test, so `Immagine::pinch` ignores a finger that went down inside `Viewer::info_rect` (measured by a canvas each frame) and everything while the menu is open; mouse events are blocked by `.occlude()`.
